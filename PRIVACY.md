# Privacy and Local Data

AgentHist is local-first. Scanning reads supported Agent history and copies parsed history into the AgentHist state directory; Desktop also creates a rebuildable search index. These files can contain complete conversation text and are not encrypted by AgentHist.

Default state locations are `%LOCALAPPDATA%\AgentHist` on Windows, `~/Library/Application Support/AgentHist` on macOS, and `$XDG_STATE_HOME/agenthist` or `~/.local/state/agenthist` on Linux. `--state-dir` can select another CLI location. Close AgentHist and resolve any pending transaction before deleting a state directory, because deletion also removes AgentHist metadata, caches, and recovery records; it does not delete native Agent history.

`.agenthist` exports contain conversation content and related resources in an unencrypted portable archive. Store and transfer them as private data. AgentHist does not migrate provider connection settings or credentials. Desktop Experience may read the selected Agent’s API URL, model and API credential into main-process memory to call that configured service; credentials are not copied into exports, logs, renderer data or reports. Secrets already written in a conversation remain part of that conversation.

Normal history scanning, browsing, conversion planning, export, and import do not send history over the network. Experience extraction sends selected history material to the selected Agent’s configured API (desktop) or the explicitly configured API/Agent CLI (CLI) only after confirmation; review the scope for secrets, provider policy, and possible charges first. Model connection checks send a small request without history. Opening an HTTPS link hands that link to the system browser.

On Windows, launching an Agent through a configured terminal briefly places a randomly named bootstrap file in the current user's temporary directory. It contains the launch plan and the process environment needed by terminals that reuse an existing process, so it can include environment-based credentials. AgentHist deletes it from the terminal bootstrap and again after acknowledgement or timeout; validation failures are handled before the file is created. A machine or process termination in that short interval can leave the file behind, so the user temporary directory should be protected like other credential-bearing application state.
