# FAQ

## Does `scan` modify Agent history?

No. `scan` copies history into the AgentHist data directory.

## Do `archive` and `delete` remove original sessions?

No. They change only the display state in AgentHist. Use `unarchive` or `undelete` to restore a session.

## How many sessions do export and import select by default?

All sessions. Use `--agent` and `--session` to narrow the selection.

Interactive import shows the complete selection before writing, so you can deselect sessions first.

## Where can I find a `session-ref`?

Run any of these commands:

```bash
agenthist history list
agenthist history search "keyword"
agenthist inspect backup.agenthist
```

A `session-ref` is generated by AgentHist to identify one source session reliably. It is separate from the session title and the Agent's internal ID.

## Will repeated imports create duplicate sessions?

Sessions with identical content appear as `already on target` and are not written again. A matching identity with different content is reported as a conflict.

## Why does import need a workspace path?

Supported Agents may organize or filter sessions by workspace. A correct target path makes the imported session visible in its intended project.

If the source directory does not exist on the new machine, choose a new directory or add `--map-path`.

## Can cross-Agent conversion lose content?

Each Agent stores history differently. Regular messages can usually be migrated, while tool state, branches, checkpoints, and attachments depend on both source and target formats.

The import preview classifies each session as `exact`, `degraded`, or `blocked` and lists the specific changes.

## Why does Codex import ask for a provider?

Codex sessions contain a provider identifier, and sessions under different providers may be displayed separately.

During import, choose the receiving machine's current provider, keep source providers, or provide a provider explicitly. AgentHist writes session records only and does not modify `config.toml`.

## Does a `.agenthist` archive contain API keys?

AgentHist does not collect Agent connection settings or credentials. Text that already appears in chat messages remains part of the exported history, so treat `.agenthist` archives as private data.

## Which commands write to native Agent history?

`import --apply` and `codex provider unify --apply` write native history and create transactions.

`doctor`, `scan`, `history`, `export`, `inspect`, and dry runs do not write native Agent history.
